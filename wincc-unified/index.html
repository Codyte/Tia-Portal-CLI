WinCC Unified screens and tags from the command line

The HMI side. These verbs read a WinCC Unified station and build it: tags, screens, and the items on a screen, each addressable without clicking through the editor.

26 verbs of 348 · TIA Portal V19, V20 and V21

tia unified-info [--device X]
read-only: the WinCC Unified software of the panel
tia list-unified-tags [--device X] [--table T]
read-only: the tags of one table, or of every table when --table is left out
tia add-unified-tag --table T --name N [--type D] [--connection C] [--plc-tag DB.member] [--address A] [--device X] [--apply]
Create takes the name only
tia delete-unified-tag --table T --name N [--device X] [--apply]
See the verb's own --help.
tia create-unified-screen --name N [--group A/B] [--device X] [--apply]
--group is the screen folder of the project tree, created when missing
tia delete-unified-screen --name N [--device X] [--apply]
takes the items with it
tia delete-unified-item --screen S --item I [--device X] [--apply]
See the verb's own --help.
tia list-unified-items --screen S [--device X]
read-only: the items of the screen with kind and geometry
tia add-unified-item --screen S [--kind K] [--name N] [--type T] [--set A=V ...] [--device X] [--apply]
without --kind it answers the kinds the composition accepts, which is the list to pick from
tia set-unified-item --screen S --item I [--set A=V | --set Part.A=V | --set Events.E=script ...] [--part P] [--device X] [--apply]
without --set it lists the attributes the item exposes
tia list-dynamizations --screen S [--item I] [--device X]
read-only: the dynamizations of a screen item
tia set-dynamization --screen S [--item I] --property P [--kind K] [--set A=V ...] [--device X] [--apply]
binds a property: --kind takes tag, expression, resourcelist, tagparameter, flashing or script, and creates the dynamization when the property has none
tia delete-dynamization --screen S [--item I] --property P [--device X] [--apply]
See the verb's own --help.
tia add-mapping-entry --screen S [--item I] --property P --kind range|singlebit|multibit [--set A=V ...] [--device X] [--apply]
an entry in the mapping table of the dynamization
tia set-mapping-entry --screen S [--item I] --property P --index N [--set A=V ...] [--device X] [--apply]
writes an entry that already exists
tia delete-mapping-entry --screen S [--item I] --property P --index N [--device X] [--apply]
the index is the one list-dynamizations prints
tia list-unified-objects [--kind K] [--device X]
read-only: without --kind, every kind of named object the Unified software carries with its count and whether the composition can create one
tia add-unified-object --kind K --name N [--type T] [--set A=V ...] [--device X] [--apply]
Create takes the name only
tia set-unified-object --kind K --name N [--set A=V ...] [--device X] [--apply]
without --set it lists what the object exposes
tia delete-unified-object --kind K --name N [--device X] [--apply]
See the verb's own --help.
tia export-unified --kind K [--name N] [--out D] [--device X]
writes the exchange files of a Unified composition into a directory: tags, script modules and text/graphic lists are the kinds that export
tia import-unified --kind K --dir D [--name N] [--device X] [--apply]
the pair of export-unified
tia export-unified-screen --screen S [--file F.json] [--device X]
read-only: the whole screen as one JSON document, format tia-cli/unified-screen v1
tia import-unified-screen --file F.json [--screen NEW] [--group A/B] [--replace OLD=NEW ...] [--device X] [--apply]
--group, or the document's group key, puts the new screen in that folder, created when missing
tia validate-unified --kind K [--name N] [--device X]
read-only: what the Portal would complain about, property by property, without compiling
tia set-unified-setting [--name A] [--value V] [--owner O] [--device X] [--apply]
one runtime setting by attribute name, looked up in HmiRuntimeSetting and then in the settings objects it carries
